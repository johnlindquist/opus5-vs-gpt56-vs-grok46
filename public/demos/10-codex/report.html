State-transition model

A cancelled running function may ignore its signal. Its caller is rejected immediately, while the slot and live ID remain held until the function exits.

Legacy failure modes → fixes

Legacy failureRefactored behavior
Concurrency accepted fractions, zero edge cases, and values above a safe ceiling.Constructor enforces integer 1…32.
options.priority || 0 and sort alone did not encode stable FIFO intent.Nullish defaults plus a monotonic insertion sequence form a total order.
Duplicate IDs could overwrite active map entries.A single live registry rejects duplicates across all three live phases.
Synchronous task throws escaped before Promise machinery was attached.Task invocation occurs inside a promise continuation.
First retry waited 50ms, not 25ms.One-based formula is 25 × 2^(retryNumber−1).
Retry backoff was invisible, uncancellable, and could outlive “drain.”Each item owns one timer; retry-waiting is counted and cancellation clears it.
Pending cancellation removed work but never settled its promise.Every cancellation rejects once with typed AbortError.
Running cancellation could still retry after abort.Cancellation is sticky; late fulfillment/rejection only releases ownership.
Drain resolved when pending was empty—even with active work.Drain resolves only when the authoritative live registry reaches zero.
Close threw synchronously from add.All invalid additions uniformly return rejected promises with typed errors.
Observer hooks did not exist.Frozen typed events are emitted; throwing listeners are isolated.
