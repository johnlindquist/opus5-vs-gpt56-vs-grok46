Before / after architecture

One 120-line class where every concern shared the same mutable fields, replaced by five modules with one owner per concern — and, critically, a named state for every moment in a job's life.

before legacy/queue.ts · 120 lines

JobQueue one file, one class
Five private fields carry all state, and no field says what a job is:
  • #pending — array, re-sorted on every add
  • #active — id → controller, no duplicate check
  • #running — counter, decremented before retries
  • #drainers — flushed only from .finally
  • #closed — boolean
#pump() the whole state machine
Dequeue, start, resolve, retry, re-queue, drain and slot accounting all interleaved in one promise chain — with run() called inside a new Promise executor, and retry timers owned by nobody.
setTimeout hardcoded
No seam, so every test must sleep. Nothing reports what the queue is doing.
→

after src/ · 5 modules

job-queue.ts the state machine
One record per live job with an explicit state field, a sorted-on-insert pending queue, an id registry, and a reentrancy-safe pump. Each record owns its single retry timer.
types.ts public contract
JobFunction, AddOptions, QueueStats, QueueEvents, and the two seams.
errors.ts typed failures
One QueueError root: closed, duplicate, invalid, abort. Callers discriminate on a class, not a string.
backoff.ts delay + timer seam
The pure curve, the host timer wrapper, and ManualScheduler — virtual time plus a leak counter for tests.
events.ts typed emitter
Synchronous dispatch over a snapshot; a throwing listener is contained and reported out of band.

State transitions

Three live states and three terminal ones. Solid edges are ordinary progress; dashed edges are cancel(), which is terminal from every live state.

Legacy failure modes and their fixes

#DefectWhat the legacy code does ConsequenceFix
0 Synchronous throws bypass everything
proof: #0 a synchronous throw escapes #pump
 #pump calls item.run(signal) from inside the new Promise executor in add, so a synchronous throw unwinds the executor rather than reaching .catch. The promise rejects immediately with retries ignored, and #running / #active are never cleaned up — at concurrency: 1 the queue wedges permanently. run is invoked inside its own try/catch and the throw is converted to a rejection, taking the identical path — retries included — as an async failure.
1 Retry-waiting is not a state
proof: #1/#2 drain resolves while a retry is still armed
 #running is decremented in .finally() even when a retry has just been armed, and the item sits in neither #pending nor #active during backoff. Work that is sleeping between attempts is invisible to every counter in the queue. An explicit retry-waiting state with its own counter, reported by stats() alongside pending and running.
2 drain() resolves early
proof: #1/#2 drain resolves while a retry is still armed
 drain() resolves as soon as #pending is empty, and returns an already-resolved promise if the array happens to be empty at call time. Callers “drain” a queue that still has jobs executing and retry timers armed. Resolves only when pending, running, and retryWaiting are all zero — re-evaluated after every transition, including cancellation and retry re-queue.
3 Retries lose their priority
proof: #3 a retried job is re-queued without re-sorting
 A retried item is pushed back onto #pending; the sort only ever runs inside add. A priority: 100 retry runs after a priority: -100 job that was queued later. The pending queue is kept ordered on insert (priority desc, sequence asc), so a retry re-enters at a defined position in its own priority band.
4 Backoff is off by one
proof: #4 the first retry waits 50ms instead of 25ms
 item.attempt += 1 runs before computing 25 * 2 ** item.attempt. The first retry waits 50ms instead of the documented 25ms; every delay in the curve is doubled. retry is 1-based and 25 * 2 ** (retry - 1) is a pure function in src/backoff.ts with its own unit test.
5 Cancelling a running job retries it
proof: #5 cancelling a running job retries it instead of ending it
 cancel calls controller.abort() and nothing else. The caller's promise never settles, and when the task rejects in response to the signal the job is retried after having been cancelled. Cancellation is terminal: reject once with AbortError, mark the attempt abandoned, release the slot and the id, and discard whatever the attempt eventually produces.
6 Jobs resurrect out of backoff
proof: #6 cancelling during retry backoff returns false
 During backoff the item is in neither #pending nor #active, so cancel cannot find it. cancel returns false, the timer survives, and the job runs after being cancelled. Retry-waiting is a live state; each record owns its single timer, and cancelling clears it and decrements the counter in the same step.
7 Duplicate ids clobber each other
proof: #7 duplicate ids evict each other
 #active is keyed by id with no duplicate check. Two jobs run under one id; the second evicts the first from #active, leaving the first permanently uncancellable. Adding an id that is pending, running, or retry-waiting rejects with DuplicateJobIdError. The id is released the moment the job reaches a terminal state.
8 Two error channels, no types
proof: #8 add throws synchronously after close
 add throws a bare new Error("closed") after close. Callers need both try/catch and .catch, and have nothing to discriminate on but a string. add never throws. Every rejected addition is a rejected promise carrying a typed error: QueueClosedError, DuplicateJobIdError, or InvalidJobError.
9 NaN concurrency deadlocks silently
proof: #9 a NaN concurrency is accepted and deadlocks the queue
 if (concurrency < 1) throw — but NaN < 1 is false. new JobQueue(NaN) builds a queue where 0 < NaN is also false, so it never starts anything and every add hangs. 1.5 and 1e9 are accepted too. Integer range check, 1 through 32, with a typed InvalidConcurrencyError thrown at construction.
10 Nothing is observable or testable
proof: (structural — every test in the left-hand column depends on it)
 No stats, no events, no state field, and setTimeout hardcoded. Nothing to assert against; tests must sleep and guess, which is why the legacy suite below still uses real delays. stats(), six typed events, and an injectable Scheduler — the replacement's 24 tests run in tens of milliseconds and assert on leaked timers directly.

Corrected semantics at a glance

Ordering

Priority descending, then FIFO by insertion. The pending queue is kept sorted on insert, so a retry re-enters at a defined position in its own priority band instead of at the tail.

Concurrency

An integer from 1 through 32, validated at construction. At most that many jobs execute at once; a slot is released when an attempt settles or when a running job is cancelled.

Identity

One live record per id while pending, running, or retry-waiting. Duplicates reject with DuplicateJobIdError; the id is reusable the instant the job reaches a terminal state.

Retries

retries: n means n attempts after the first. Retry k waits 25 · 2^(k−1) ms — 25, 50, 100. A synchronous throw follows the identical path as a rejection.

Cancellation

Terminal from any live state, rejecting exactly once with AbortError. Running jobs get their signal aborted and never retry; backoff timers are cleared.

Close

Refuses new additions with a typed QueueClosedError while letting accepted work — retries included — settle. There is no reopen.

Drain

Resolves only when pending, running, and retry-waiting are all zero. Every concurrent caller resolves, and jobs added while a drain is outstanding are included in it.

Error surfacing

add never throws: every rejected addition is a rejected promise, so one catch covers closed queues, duplicate ids, bad arguments, cancellation, and task failure alike.
